# 开发过程 FAQ

## Q01: Prisma Client 生成失败，文件被锁定

**问题描述**：运行 `npx prisma generate` 时报错 "The `prisma-client-js` query engine file was locked"

**原因**：有其他 Node 进程正在使用 Prisma Client

**解决方案**：
```powershell
# 1. 关闭所有 Node 进程
taskkill /F /IM node.exe

# 2. 清除 .prisma 缓存
Remove-Item -Path "node_modules\.prisma" -Recurse -Force

# 3. 重新生成
npx prisma generate
```

## Q02: 注册 API 创建默认学科失败

**问题描述**：用户注册时返回 500 错误，日志显示 "Unique constraint failed"

**原因**：`prisma.subject.createMany` 会因 `code` 字段唯一约束冲突而失败

**解决方案**：
在 `src/app/api/auth/register/route.ts` 中添加 `skipDuplicates: true`：
```typescript
await prisma.subject.createMany({
  data: [...],
  skipDuplicates: true,
});
```

**相关文件**：`src/app/api/auth/register/route.ts`

---

## Q03: 题目列表页面报错 "questions.filter is not a function"

**问题描述**：访问 `/dashboard/questions` 时页面报错

**原因**：API 返回 `{ questions: [...], pagination: {...} }`，但前端直接用 `setQuestions(data)` 设置整个对象，而不是 `data.questions`

**解决方案**：
在 `src/app/dashboard/questions/page.tsx` 中修复：
```typescript
// 错误写法
setQuestions(data);

// 正确写法
setQuestions(data.questions || []);
```

**相关文件**：`src/app/dashboard/questions/page.tsx`

---

## Q04: 题目管理页面加载失败

**问题描述**：访问 `/dashboard/questions/new` 页面被中止

**排查**：
1. 确认 `QuestionForm` 组件存在且路径正确 ✅
2. 确认开发服务器已重启
3. 检查控制台错误日志

**解决方案**：重启发服务器即可

## 001 - Tailwind CSS 样式不加载

### 问题详情

**发现时间**: 2026-05-11 19:30:00

**错误信息**: 无错误信息，页面正常显示但完全没有样式（白色背景、黑色默认文字）

**影响范围**:
- 所有页面样式丢失
- Tailwind CSS 类（如 `bg-primary`、`text-foreground`）不生效
- 自定义 CSS 变量（如 `--primary`）未应用

**触发条件**:
- 首次创建项目后运行 `npm run dev`
- 重新安装依赖后

---

### 问题原因

1. **PostCSS 配置文件格式问题**:
   - 原配置文件为 `postcss.config.mjs`（ES Module 格式）
   - Next.js 14.x 对 `.mjs` 格式的 PostCSS 配置支持不稳定
   - 导致 Tailwind CSS 插件未被正确加载

2. **现象分析**:
   - 浏览器 Network 标签中 `layout.css` 返回 200（文件存在）
   - 但 CSS 内容只包含 `@tailwind` 指令，**没有编译后的类**
   - 例如缺少 `.bg-primary { background-color: hsl(var(--primary)); }` 等已编译样式

---

### 解决方案

**方案一（推荐）**: 修改 PostCSS 配置文件格式

**文件**: `postcss.config.js`（删除 `.mjs` 后缀，改用 `.js`）

**操作步骤**:

1. 删除原有的 `postcss.config.mjs` 文件

2. 创建新的 `postcss.config.js` 文件：

```javascript
module.exports = {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};
```

3. 清除 Next.js 缓存并重启：

Remove-Item -Recurse -Force .next
npm run dev
```

4. 硬刷新浏览器：**Ctrl + Shift + R**（Windows）或 **Cmd + Shift + R**（Mac）

**方案二（备用）**: 保留 `.mjs` 但检查配置

如果方案一不可行，确保 `postcss.config.mjs` 内容正确：

```javascript
export default {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};
### 验证方法

1. 启动开发服务器后，打开浏览器 DevTools（F12）

2. 切换到 **Network** 标签，刷新页面

3. 找到 `layout.css` 文件，点击查看 **Response** 标签

4. 确认 CSS 内容包含已编译的 Tailwind 类：
   ```css
   .bg-primary { background-color: hsl(var(--primary)); }
   .text-muted-foreground { color: hsl(var(--muted-foreground)); }
   .border-border { border-color: hsl(var(--border)); }
   ```

5. 或者直接在浏览器中查看页面，应显示蓝色主色调背景和正确样式

---

### 相关文件

| 文件路径 | 修改类型 |
|----------|----------|
| `postcss.config.js`（新建） | 创建文件 |
| `postcss.config.mjs` | 删除 |
| `.next/` | 清除缓存 |

---

### 预防措施

1. **使用 `.js` 而非 `.mjs`**:
   - Next.js 14.x 建议使用 `postcss.config.js`
   - 避免使用实验性的 ESM 配置格式

2. **安装后验证样式**:
   - 执行 `npm install` 后运行 `npm run dev`
   - 访问首页确认样式正常加载

3. **缓存清理**:
   - 遇到样式问题时，首先尝试 `Remove-Item -Recurse -Force .next`
   - 必要时删除 `node_modules` 重新安装

4. **检查 Tailwind 配置**:
   - 确保 `tailwind.config.ts` 中 `content` 数组包含所有源码路径：
   ```typescript
   content: [
     './src/pages/**/*.{js,ts,jsx,tsx,mdx}',
     './src/components/**/*.{js,ts,jsx,tsx,mdx}',
     './src/app/**/*.{js,ts,jsx,tsx,mdx}',
   ],
   ```

## 002 - next-auth v5 beta 与 Next.js 14.1.0 不兼容

### 问题详情

**发现时间**: 2026-05-11 20:33:00

**错误信息**:
```
TypeError: next_dist_server_web_exports_next_request__WEBPACK_IMPORTED_MODULE_0__ is not a constructor
    at reqWithEnvURL (webpack-internal:///(rsc)/./node_modules/next-auth/lib/env.js:16:12)
    at httpHandler (webpack-internal:///(rsc)/./node_modules/next-auth/index.js:143:139)
**影响范围**:
- 登录页面 `/login` 无法正常工作
- 所有依赖认证的页面访问异常
- API 路由 `/api/auth/*` 报错

**触发条件**:
- 登录页面提交表单后

---

### 问题原因

**next-auth v5 (beta.15)** 与 **Next.js 14.1.0** 存在兼容性问题：
- next-auth 5.0.0-beta.15 使用了较新的 Next.js App Router API
- 与当前稳定版 Next.js 14.1.0 的内部实现不完全兼容
- 导致 Webpack 打包时出现类型错误

---

### 解决方案

**降级到稳定版本**:

```powershell
# 1. 卸载当前版本
npm uninstall next-auth @auth/prisma-adapter

# 2. 安装稳定版本
npm install next-auth@^4.24.5 @auth/prisma-adapter@^1.5.0

# 3. 清除缓存
Remove-Item -Recurse -Force .next

# 4. 重启开发服务器
npm run dev
```

---

### 验证方法

1. 重启后访问 `http://localhost:3000/login`

2. 使用测试账号登录，确认：
   - 页面正常显示，无报错
   - 登录成功后跳转到 `/dashboard`
   - 导航栏显示用户信息

---

### 相关文件

| 文件路径 | 修改类型 |
|----------|----------|
| `package.json` | 降级依赖版本 |
| `src/lib/auth.ts` | 需适配 v4 API（如有变化） |

---

### 预防措施

1. **避免使用 beta 版本**:
   - 生产环境建议使用稳定版 `next-auth@^4.24.5`
   - beta 版本仅用于测试新功能

2. **版本组合建议**:
   - Next.js 14.1.0 + next-auth 4.24.x（稳定）
   - Next.js 15.x + next-auth 5.x（beta）

3. **升级前检查兼容性**:
   - 查看 next-auth GitHub 的兼容性表
   - 在测试环境验证后再部署

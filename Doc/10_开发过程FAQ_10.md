## 家长推题功能 - 需求分析与设计方案

### 一、需求背景

**用户场景**：
- 家长录入题目到题库后，希望能把题目推送给孩子做练习
- 孩子可以用自己的账号登录，看到家长布置的任务
- 孩子也可以自己从题库选择题目练习

**核心功能**：
1. **家长手动推题**：选择题目 → 指定孩子 → 发送任务
2. **孩子接收任务**：登录后看到待完成任务列表
3. **孩子自选练习**：从题库浏览/搜索 → 自选练习

### 三、设计方案

#### 3.1 新增数据库表

**方案A：新建 `PracticeTask` 表（推荐）**

```prisma
// 练习任务表 - 家长推送给孩子的练习任务
model PracticeTask {
  id                 String        @id @default(cuid())
  parentId           String        // 家长ID (关联 User)
  childId            String        // 孩子ID (关联 ChildAccount)
  subjectId          String?       // 科目ID (关联 Subject, 可选)
  title              String        // 任务名称，如 "数学作业第3章"
  description        String?       // 任务描述/备注
  questionIds        String[]      // 题目ID列表
  questionCount      Int           @default(0)  // 题目数量
  dueDate            DateTime?     // 截止日期 (可选，不填时默认今天+7天)
  status             TaskStatus    @default(PENDING)  // 任务状态
  allowSkip          Boolean       @default(true)     // 是否允许跳过题目
  requireConfirmation Boolean      @default(false)    // 是否需要家长确认完成
  completedAt        DateTime?     // 完成时间
  createdAt          DateTime      @default(now())
  updatedAt          DateTime      @updatedAt
  
  // 关联
  parent             User          @relation(fields: [parentId], references: [id], onDelete: Cascade)
  child              ChildAccount  @relation(fields: [childId], references: [id], onDelete: Cascade)
  subject            Subject?      @relation(fields: [subjectId], references: [id])
  
  @@index([parentId])
  @@index([childId])
  @@index([status])
  @@map("practice_tasks")
}

enum TaskStatus {
  PENDING         // 待完成
  IN_PROGRESS     // 进行中
  PENDING_CONFIRM // 待家长确认
  COMPLETED       // 已完成
  OVERDUE         // 已逾期
  CANCELLED       // 已取消
}
```

**方案B：复用 `PracticeSession`（不推荐）**

- 缺点：`PracticeSession` 设计用于记录孩子实际练习结果，不适合作为任务模板
- 优点：无需新建表

**结论**：采用方案A，新建 `PracticeTask` 表，保持职责单一。

#### 3.2 API 设计

**1. 创建推题任务**

```
POST /api/practice/tasks
```

请求体：
```json
{
  "childId": "child_xxx",
  "subjectId": "math",          // 可选
  "title": "第五章练习",
  "description": "周末作业",
  "questionIds": ["q1", "q2", "q3"],
  "dueDate": "2026-05-15",      // 可选，不填时默认今天+7天
  "allowSkip": true,            // 是否允许跳过题目，默认 true
  "requireConfirmation": false  // 是否需要家长确认，默认 false
}
```

响应：
```json
{
  "id": "task_xxx",
  "title": "第五章练习",
  "questionCount": 3,
  "status": "PENDING",
  "child": { "id": "child_xxx", "nickname": "小明" },
  "createdAt": "2026-05-12T20:30:00Z"
}
```

**2. 获取我推送的任务列表（家长端）**

```
GET /api/practice/tasks?parentId=xxx&status=PENDING
```

响应：
```json
{
  "tasks": [
    {
      "id": "task_xxx",
      "title": "第五章练习",
      "child": { "id": "child_xxx", "nickname": "小明" },
      "questionCount": 3,
      "status": "PENDING",
      "dueDate": "2026-05-15",
      "createdAt": "2026-05-12"
    }
  ],
  "total": 10
}
```

**3. 获取我的任务列表（孩子端）**

```
GET /api/practice/tasks/child?childId=xxx&status=PENDING
```

响应：同上

**4. 完成任务（孩子提交 / 家长确认）**

```
POST /api/practice/tasks/:id/complete
```

请求体（家长确认时）：
```json
{
  "action": "confirm"  // confirm = 家长确认完成
}
```

请求体（孩子提交时）：
```json
{
  "action": "submit"  // submit = 孩子提交答案
}
```

响应：
```json
{
  "id": "task_xxx",
  "status": "COMPLETED",  // 或 "PENDING_CONFIRM"（如果需要家长确认）
  "completedAt": "2026-05-12T21:00:00Z"
}
```

**5. 确认完成任务（家长手动确认）**

```
POST /api/practice/tasks/:id/confirm
```

**6. 删除任务**

```
DELETE /api/practice/tasks/:id
```

**7. 发送站内通知（创建任务时自动调用）**

```
POST /api/notifications
```

```json
{
  "userId": "child_xxx",
  "type": "TASK_ASSIGNED",
  "title": "新任务通知",
  "content": "\"第五章练习\" 已发布，共 3 道题目",
  "taskId": "task_xxx"
}
```

| # | 问题 | 确认结果 |

#### 5.1 任务完成逻辑（确认）

孩子作答完成后，任务状态更新规则：

```
孩子提交答案
    │
    ├── 家长设置"需要确认" = true
    │       │
    │       └── 状态 → 待家长确认
    │               │
    │               └── 家长手动点击"确认完成" → 状态 → 已完成
    │
    └── 家长设置"需要确认" = false
            │
            └── 状态 → 已完成（自动）
```

#### 5.2 跳过题目设置（确认）

在推送对话框中新增开关：

```
┌─────────────────────────────────────────┐
│  允许跳过题目：                          │
│  ┌─────────────────────────────────┐   │
│  │ ○ 不允许（必须按顺序作答）         │   │
│  │ ○ 允许（可以跳过暂时不会的题目）   │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

默认值：允许（true），孩子可以先跳过不熟悉的题目。

#### 5.3 站内通知（确认）

当家长推送任务时，自动给孩子发送站内通知：

```
通知内容格式：
📚 新任务通知
"第五章练习" 已发布，共 3 道题目
截止日期：5月15日
[立即查看]
```

#### 5.4 截止日期默认值（确认）

- 必填：否
- 默认值：今天 + 7 天
- 家长可修改

- 分别验证权限：孩子只能访问自己的任务，家长只能访问自己推送的任务

**受影响文件**：
- `src/app/api/practice/tasks/[id]/route.ts`
- `src/app/api/practice/tasks/[id]/submit/route.ts`

**修复后代码**（任务详情 API）：
```typescript
import { getChildSession } from "@/lib/child-session";
import { getServerSession } from "next-auth";

const childSession = await getChildSession();
const parentSession = await getServerSession(authOptions);

let hasPermission = false;
if (childSession && task.childId === childSession.child.id) {
  hasPermission = true;
} else if (parentSession?.user?.id && task.parentId === parentSession.user.id) {
  hasPermission = true;
}
```

**修复后代码**（提交 API）：
```typescript
import { getChildSession } from "@/lib/child-session";

const session = await getChildSession();
```

1. 在文件顶部添加 `getQuestionContentPreview` 纯函数，支持多种 content 格式的解析
2. 更新 JSX 模板，使用该函数生成预览文本

**修复代码**：

```tsx
// 文件顶部（import 之后、export default 之前）
function getQuestionContentPreview(content: any): string {
  if (!content) return '';

  // 情况1：字符串（HTML 或纯文本）
  if (typeof content === 'string') {
    const text = content
      .replace(/<br\s*\/?>/gi, '\n')
      .replace(/<[^>]*>/g, '')
      .trim();
    if (!text) return '[图片/富媒体题目]';
    return text.length > 30 ? text.slice(0, 30) : text;
  }

  // 情况2：Tiptap JSON 格式 { type: "doc", content: [...] }
  if (content?.type === 'doc' && Array.isArray(content.content)) {
    const texts: string[] = [];
    for (const block of content.content) {
      if (Array.isArray(block?.content)) {
        for (const inline of block.content) {
          if (inline?.type === 'text' && inline.text) texts.push(inline.text);
        }
      }
      if (block?.type === 'image') return '[图片题目]';
    }
    const result = texts.join(' ').trim();
    if (!result) return '[图片/富媒体题目]';
    return result.length > 30 ? result.slice(0, 30) : result;
  }

  // 情况3：旧 Tiptap JSON 格式 { blocks: [...] }
  if (Array.isArray(content?.blocks)) {
    const text = content.blocks
      .filter((b: any) => b.type === 'paragraph')
      .map((b: any) => typeof b.content === 'string' ? b.content : '')
      .join(' ')
      .trim();
    if (text) return text.length > 30 ? text.slice(0, 30) : text;
  }

  return '';
}
```

**JSX 模板更新**：
```tsx

  return (
    <div key={q.id} className="flex items-center justify-between py-2 border-b last:border-0">
      <span className={`text-sm truncate max-w-[200px] ${!preview ? 'text-muted-foreground italic' : ''}`}>
        {preview || '暂无文本预览'}
      </span>
      <span
        className="text-xs px-2 py-1 rounded flex-shrink-0"
        style={{ backgroundColor: q.subject.color + '20', color: q.subject.color }}
      >
        {q.subject.name}
      </span>
    </div>
  );
})}
```

### Bug 修复 #25：Tiptap 编辑器无法回显外部传入的 value（题目内容/答案/解析为空）

**问题描述**：
- 编辑题目时，题目内容、答案、解析的富文本编辑器全部为空
- 数据库中明明有数据，但表单不显示

**根本原因**：
- Tiptap `useEditor` 的 `content: value` 属性**仅在编辑器首次创建时生效**
- 编辑模式下的数据流：Server Component → `initialData` → `useState` → `value` prop → Tiptap 编辑器
- 由于 SSR/CSR 时序差异或 React StrictMode 双重渲染，编辑器初始化时 `value` 可能还未就绪
- 之后 `value` 变化了，编辑器因为不会再读取 `content` 而保持空白

**受影响文件**：
- `src/components/dashboard/tiptap-editor.tsx`（题目内容编辑器）
- `src/components/dashboard/tiptap-simple-editor.tsx`（答案/解析编辑器）

**修复方案**：
在两个编辑器组件中各添加一个 `useEffect`，监听外部 `value` 变化并同步到编辑器：

```tsx
// 在 const editor = useEditor({...}) 之后添加：
useEffect(() => {
  if (editor && value !== editor.getHTML()) {
    editor.commands.setContent(value || '');
  }
}, [value, editor]);
```

**注意**：必须将 `useEffect` 放在 `const editor = useEditor({...})` 之后声明，否则会报 `"editor" is not defined` 错误（JavaScript 不允许在变量声明前引用）。

### Bug 修复 #26：编辑题目时答案解析字段为空（Json 类型未序列化）

**问题描述**：
- 编辑题目时，题目内容、答案、解析全部为空
- 数据库中 `content`、`answer`、`analysis` 字段类型是 `Json`（JSON 对象）
- 但编辑页面直接传给了表单，而表单和 Tiptap 编辑器期望的是 string 类型

**受影响文件**：
- `src/app/dashboard/questions/[id]/edit/page.tsx`

**修复方案**：
在编辑页面中，将数据库的 Json 字段转为字符串传给表单：

```typescript
// DB difficulty 是 Int (1-5)，需要映射为表单的 Difficulty 枚举
const difficultyMap: Record<number, string> = {
  1: "EASY",
  2: "MEDIUM",
  3: "MEDIUM",
  4: "HARD",
  5: "HARD",
};
const difficultyValue = question.difficulty
  ? (difficultyMap[question.difficulty] || "MEDIUM")
  : "MEDIUM";

// DB content/answer/analysis 是 Json 类型，需要转为 string
const contentStr = typeof question.content === "string"
  ? question.content
  : JSON.stringify(question.content);
const answerStr = typeof question.answer === "string"
  ? question.answer
  : JSON.stringify(question.answer);
const analysisStr = question.analysis
  ? (typeof question.analysis === "string"
    ? question.analysis
    : JSON.stringify(question.analysis))
  : "";

const initialData = {
  content: contentStr,
  type: question.type,
  subjectId: question.subjectId,
  gradeId: question.grade || undefined,
  difficulty: difficultyValue as "EASY" | "MEDIUM" | "HARD",
  answer: answerStr,
  explanation: analysisStr, // DB 的 analysis -> 表单的 explanation
  tags: Array.isArray(question.tags)
    ? question.tags.join(", ")
    : (question.tags || ""),
};
```

**字段映射总结**：

| DB 字段 | 类型 | 表单字段 | 处理方式 |
|---------|------|----------|----------|
| `content` | Json | `content` | `JSON.stringify()` |
| `answer` | Json | `answer` | `JSON.stringify()` |
| `analysis` | Json? | `explanation` | `JSON.stringify()` 或空串 |
| `difficulty` | Int (1-5) | `difficulty` | 映射为 `EASY/MEDIUM/HARD` |
| `tags` | String[]? | `tags` | `.join(", ")` 转逗号分隔 |

**问题描述**：
- 学习报告页面"本周练习"显示 3，但完成题目=0、正确率=0%、掌握题目=0

**根因分析**：

`practice_records` 表是一张**孤儿表**（只有读取没有写入）：

### Bug 修复 #27：知识点标签（tags）无法保存和回显

**问题描述**：
- 编辑题目时，知识点标签输入框显示为空（即使创建时填写了标签）
- 创建/更新题目时，标签数据没有被保存到数据库

**根因分析**：

`Question` 模型本身**没有 `tags` 字段**，标签通过多对多关联表存储：

```
Question ←→ QuestionTag ←→ Tag
```

但整个链路都存在缺陷：

| 环节 | 问题 |
|------|------|
| **编辑页面查询** | `findUnique` 没有 include 关联表，`question.tags` 不存在 → 始终为空 |
| **创建 API (POST)** | `validatedData.tags` 被接收但未写入，既没存 metadata 也没创建 QuestionTag |
| **更新 API (PUT)** | 完全忽略 tags 字段 |

**受影响文件**：
- `src/app/dashboard/questions/[id]/edit/page.tsx`
- `src/app/api/questions/route.ts`（POST）
- `src/app/api/questions/[id]/route.ts`（PUT）

**修复方案**：

1. **编辑页面查询**：include 关联表，从 `questionTags` 提取标签名
```typescript
const question = await prisma.question.findUnique({
  where: { id: params.id },
  include: {
    questionTags: { include: { tag: true } },
  },
});

// 从关联表拼接标签名
const tagsStr = question.questionTags?.length > 0
  ? question.questionTags.map(qt => qt.tag.name).join(", ")
  : "";
```

2. **创建/更新 API**：解析逗号分隔的标签字符串，通过 `tag.upsert()` + `questionTags.create` 保存
```typescript
const tagNames = validatedData.tags
  ? validatedData.tags.split(/[,，]/).map(t => t.trim()).filter(Boolean)
  : [];

// 更新时先 deleteMany 清除旧关联，再 create 新关联
questionTags: {
  deleteMany: {},
  create: await Promise.all(tagNames.map(async (name) => {
    const tag = await prisma.tag.upsert({
      where: { userId_name: { userId, name } },
      update: {},
      create: { userId, name },
    });
    return { tagId: tag.id };
  })),
}
```

```typescript
// 修复前
analysis: validatedData.explanation ? { text: validatedData.explanation } : undefined,
// 修复后
analysis: validatedData.explanation || undefined,
```

2. **回显端**：兼容旧数据（已存为 `{ text: "..." }` 格式的记录）
```typescript
if (typeof analysisRaw === "string") {
  analysisStr = analysisRaw;
} else if (typeof analysisRaw === "object" && "text" in analysisRaw) {
  // 兼容旧的 { text: "..." } 格式数据
  analysisStr = (analysisRaw as any).text || "";
} else {
  analysisStr = JSON.stringify(analysisRaw);
}
```

### 数据库同步指南

**重要**：每次修改 Prisma Schema 后，需要同步到数据库。

**常用命令**：

```bash
# 1. 将 Schema 变更同步到数据库（不会删除数据）
npx prisma db push

# 2. 如果有数据丢失风险，使用 --accept-data-loss
npx prisma db push --accept-data-loss

# 3. 生成 Prisma Client（表结构变更后必须执行）
npx prisma generate

# 4. 查看数据库状态
npx prisma db status
```

**常见错误**：

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `Table does not exist` | 表未创建 | 运行 `npx prisma db push` |
| `Column does not exist` | 列未创建 | 运行 `npx prisma db push` |
| `Invalid relation` | 关联字段不匹配 | 检查 Schema 和数据库是否同步 |

**Schema 修改后必须执行的操作**：
1. 修改 `prisma/schema.prisma`
2. 运行 `npx prisma db push --accept-data-loss` 同步到数据库
3. 运行 `npx prisma generate` 更新 Prisma Client
4. 重启开发服务器（如果需要）
